# Криптотрейдинговый бот

Терминальный бот для линейных USDT-инструментов Bybit. Проект активно развивается, поэтому основной режим сейчас — **PAPER**: сделки моделируются локально, а реальные ордера не отправляются.

> Сначала добиваемся стабильной работы в терминале и на paper-сделках. REAL-режим используйте только после самостоятельной проверки кода, настроек и рисков.

## Быстрый запуск

Нужны Git и Python 3.10 или новее.

```bash
git clone https://github.com/kubiksoldom/-.git crypto-trading-bot
cd crypto-trading-bot
python -m venv .venv
```

Активируйте окружение:

```bash
# Linux / macOS
source .venv/bin/activate

# Windows PowerShell
.venv\Scripts\Activate.ps1
```

Установите зависимости и создайте локальный файл настроек:

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
cp .env.example .env
```

В Windows, если команды `cp` нет:

```powershell
Copy-Item .env.example .env
```

Для PAPER-режима ключи Bybit и Telegram не нужны — оставьте их пустыми. Безопасные настройки уже находятся в `.env.example`:

```env
PAPER_MODE=1
SAFE_MODE=1
TELEGRAM_ENABLED=0
FORCE_CLOSE_ON_EXIT=0
```

Запустите бота:

```bash
python main.py paper
```

Быстрая проверка одного цикла:

```bash
python main.py paper --ci --once
```

PAPER-сделки локальные, но котировки и свечи по умолчанию читаются из публичных рыночных API. Поэтому обычному запуску нужен интернет.

## Как остановить бота безопасно

Нажмите `Ctrl+C` один раз. Бот:

1. запрещает новые входы;
2. продолжает сопровождать открытые позиции;
3. сохраняет SL, TP, trailing и no-profit выходы;
4. завершает процесс только после закрытия всех позиций.

В логе появятся сообщения:

```text
[SHUTDOWN] graceful shutdown requested
[SHUTDOWN] entries disabled, managing open positions
[SHUTDOWN] all positions closed, exiting
```

`FORCE_CLOSE_ON_EXIT=1` включает отдельный опасный сценарий: при остановке все позиции закрываются принудительно. Оставляйте `0`, если такое поведение не требуется.

Команда panic также остаётся отдельным принудительным сценарием и не является обычным graceful shutdown.

## Восстановление открытых позиций

Бот сохраняет рабочее состояние позиций в `data/managed_positions.json` (или в путь из `MANAGED_POSITIONS_FILE`). Запись выполняется атомарно после открытия, изменения и закрытия позиции.

При запуске бот сверяет файл с `broker.get_positions()`:

- реальная открытая позиция всегда возвращается в цикл сопровождения, даже если её символ больше не входит в выбранные пары;
- средняя цена, направление, количество и `position_id` берутся у брокера;
- SL/TP и `trade_id` восстанавливаются из биржевых данных или локального файла;
- устаревшая локальная запись удаляется, если брокер подтверждает, что позиции уже нет;
- если SL или TP восстановить нельзя, бот пишет предупреждение.

Файл не содержит API-ключей или Telegram-токенов и исключён из Git. Не редактируйте его во время работы бота.

Важно: локальный файл не создаёт фиктивную позицию. Восстановление выполняется только для позиции, которую по-прежнему видит текущий broker/paper engine.

## Основные настройки

Все пользовательские настройки находятся в локальном `.env`:

| Переменная | Назначение |
|---|---|
| `PAPER_MODE` | `1` — моделировать сделки локально |
| `SAFE_MODE` | `1` — запретить реальные ордера |
| `TELEGRAM_ENABLED` | `1` — включить Telegram, `0` — полностью отключить |
| `TG_LOG_MODE` | Режим Telegram-логов, например `error` |
| `MAX_RUNTIME_SEC` | После этого времени запретить новые входы и дождаться закрытия позиций |
| `FORCE_CLOSE_ON_EXIT` | `1` — принудительно закрывать позиции при выходе |
| `WORK_DURATION_SEC` | Длительность рабочей сессии |
| `BREAK_DURATION_SEC` | Длительность перерыва; позиции на перерыве продолжают сопровождаться |
| `MANAGED_POSITIONS_FILE` | Необязательный путь к файлу восстановления |

Менять EMA, RSI, ATR, ML-пороги, плечо и размер позиции до завершения архитектурной проверки не рекомендуется.

## Telegram

Telegram полностью необязателен. Чтобы включить уведомления, заполните в локальном `.env`:

```env
TELEGRAM_ENABLED=1
TELEGRAM_TOKEN=
TELEGRAM_CHAT_ID=
```

Не публикуйте заполненный `.env`, не вставляйте ключи в issues, логи или pull requests.

## REAL-режим

Команда ниже запускает real-подключение, но при `SAFE_MODE=1` не должна отправлять ордера:

```bash
python main.py real --yes
```

Флаг `--unsafe` снимает защиту и разрешает реальные ордера. Это может привести к потере средств. Пока терминальная PAPER-версия не доказала стабильность, такой запуск не рекомендуется.

Для REAL нужны отдельные актуальные `BYBIT_API_KEY` и `BYBIT_API_SECRET` в локальном `.env`. Никогда не загружайте их в GitHub.

## Проверки для разработчиков

```bash
python -m pytest -q
python main.py paper --ci --once
```

Ключевые тесты сопровождения находятся в:

- `tests/test_graceful_shutdown.py`;
- `tests/test_management_symbols.py`;
- `tests/test_managed_exits.py`;
- `tests/test_position_recovery.py`.

## Где искать результаты

- `data/sessions/<дата_время>/log.txt` — консольный лог запуска;
- `data/sessions/<дата_время>/meta.json` — режим, пары и git SHA;
- `data/sessions/<дата_время>/stats.json` — итоговая статистика;
- `data/managed_positions.json` — состояние сопровождения открытых позиций.

## План развития

Текущий приоритет: стабильный терминальный бот → надёжный TradeApp → полноценное desktop-приложение → Android → iPhone. Мобильные приложения пока не входят в активный этап разработки.
